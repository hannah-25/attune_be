# 유지보수성

## 강점

- 모듈 레이아웃이 일관되어 위치 예측이 쉽다(헥사고날).
- 예외/보안/직렬화 등 횡단 관심사가 `common` 에 모여 있다.
- 테스트가 도메인 구조를 미러링한다.

## 리스크 / 부채

- 평면적이던 문서 → 하네스로 구조화(지속 갱신 필요).
- 포맷/정적분석 자동화 부재 → Spotless soft 도입(TD-3).
- 스키마 마이그레이션 도구 부재(TD-5) → 스키마 변경 추적이 수동.
- 일부 도메인은 선택적 레이어(`port/`, `infrastructure/`)를 갖고 일부는 안 가져 패턴 편차 존재.

## 유지보수 원칙

- 변경 파일 범위에서만 정리(거대 일괄 변경 금지).
- 새 모듈은 최소 형태로 시작, 필요할 때 레이어 추가.
- 드리프트는 `generate-*` 스크립트로 주기적으로 점검하고 tech-debt-tracker에 등록.
