# 약물 치료 경과 리포트 기획 명세

> 최근 선택 기간의 복용 기록과 일지를 연결하여, 기록된 변화와 반복 패턴을 이해하고 진료 상담을 준비하도록 돕는 리포트입니다. 약효를 판정하거나 의료 조언을 제공하지 않습니다.

---

## 1. 제품 목표

에이튠의 **약물 치료 경과 리포트**는 다음 질문에 답합니다.

- 약을 계획대로 얼마나 복용하고 기록했는가?
- 복용 기록이 있는 날과 그렇지 않은 날에 어떤 차이가 있었는가?
- 어떤 시간대에 증상·실수·부작용 기록이 자주 나타났는가?
- 상담 또는 복용 정보 변경 전후에 기록 패턴이 어떻게 달라졌는가?
- 다음 상담에서 어떤 내용을 확인하면 좋은가?

AI는 약효를 판단하는 분석가가 아니라, 서버가 계산한 기록 패턴을 사용자가 이해하기 쉬운 문장으로 설명하는 역할을 담당합니다.

---

## 2. 현재 백엔드 데이터 구조

### 복용 데이터

| 엔티티 | 분석에 사용하는 필드 |
| --- | --- |
| `UserMedication` | 상담, 약·용량, 활성 상태, `startedAt`, `endAt` |
| `UserMedicationSchedule` | 예정 복용 시각 `doseTime` |
| `UserMedicationLog` | 기록 시각 `takenAt`, `TAKEN · SKIPPED · MISSED`, 활성 상태 |

현재 실제 서비스에서는 `TAKEN`, `SKIPPED`만 생성합니다. `MISSED`는 enum에 존재하지만 생성 로직은 없으므로 MVP 분석에서 사용하지 않습니다.

`takenAt`은 사용자가 복용 또는 건너뛰기 버튼을 누른 시각입니다. 실제 복용 시각과 다를 수 있습니다.

### 일지 데이터

| 영역 | 엔티티 | 시간 기준 |
| --- | --- | --- |
| 감정·증상 | `ConditionLog` | `checkedAt: LocalDateTime` |
| 부작용 | `SideEffectLog` | `checkedAt: LocalDateTime` |
| 업무 실수·불편 | `TroubleLog` | `checkedAt: LocalDateTime` |
| 목표 점수 | `DailyGoalLog` | `date: LocalDate` |
| 수면·식사 | `DailyStatusLog` | `date: LocalDate` |
| 메모 | `Memo` | `journalDate: LocalDate` |

감정·증상, 부작용, 실수·불편의 `checkedAt`은 사용자가 체크 버튼을 누른 시각입니다. 실제 증상 발생 시각과 다를 수 있습니다.

## 3. 분석 기간

### 기본 및 직접 선택

- 기본값: 최근 30일
- 직접 선택: 최소 7일, 최대 90일
- 미래 날짜 선택 불가
- 사용자 현지 시간대를 기준으로 기간 계산

### 상담 일자 기반 빠른 선택

사용자는 상담 기록을 기준으로 분석 기간을 빠르게 선택할 수 있습니다.

- 최근 상담 이후
- 특정 상담 이후
- 이전 상담부터 다음 상담까지

상담 기준 기간도 최대 90일까지 허용합니다. 선택된 기간이 7일 미만이면 리포트를 생성하지 않고 기록이 더 필요하다고 안내합니다.

## 4. 분석 대상

MVP에서는 사용자의 **전체 복용 기록을 하나의 타임라인으로 합쳐 분석**합니다.

복용 시간이 서로 구분되므로 시간대별 기록 패턴을 관찰할 수 있지만, 특정 증상이 특정 약 때문에 발생했다고 단정하지 않습니다.

허용 표현:
> 아침 복용 기록이 있는 날에는 오후 FOGGY 기록이 적었어요.

금지 표현:
> 아침에 복용한 특정 약이 FOGGY를 줄였어요.

같은 시간대에 여러 약의 복용 기록이 있으면 전체 복용 기록으로 함께 처리합니다.

## 5. 복용 상태 정의

| 상태 | 의미 | MVP 사용 여부 |
| --- | --- | --- |
| `TAKEN` | 사용자가 복용했다고 기록 | 사용 |
| `SKIPPED` | 사용자가 건너뛰기로 기록 | 사용 |
| `UNRECORDED` | 예정 일정에 아무 기록도 없음 | 계산으로 생성 |
| `MISSED` | 미복용 확정 상태 | 사용하지 않음 |

`UNRECORDED`는 실제 미복용인지, 복용 후 기록하지 않은 것인지 알 수 없습니다. 따라서 미복용으로 표현하지 않습니다.

---

## 6. 복용 통계

### 복용 기록률

```
복용 기록률 = TAKEN / 전체 예정 복용 일정
```

> 예정된 60회 중 48회 복용 기록이 있어요.

### 복용 여부 기록률

```
복용 여부 기록률 = (TAKEN + SKIPPED) / 전체 예정 복용 일정
```

> 예정된 60회 중 55회의 복용 여부를 기록했어요.

예시:

| 상태 | 횟수 |
| --- | --- |
| TAKEN | 48회 |
| SKIPPED | 7회 |
| UNRECORDED | 5회 |
| 복용 기록률 | 80% |
| 복용 여부 기록률 | 92% |

## 7. 날짜 그룹 비교

복잡한 일일 복용률 분류 대신 날짜마다 다음 우선순위로 하나의 그룹에 포함합니다.

| 우선순위 | 그룹 | 기준 |
| --- | --- | --- |
| 1 | 복용 기록이 있는 날 | `TAKEN`이 한 건 이상 존재 |
| 2 | 건너뛰기만 기록된 날 | `TAKEN` 없이 `SKIPPED`가 한 건 이상 존재 |
| 3 | 복용 여부가 기록되지 않은 날 | `TAKEN`, `SKIPPED` 모두 없음 |

예정 3회 중 2회 복용하고 1회를 건너뛴 날은 `복용 기록이 있는 날`로 분류합니다. 일일 상세 내역에는 `TAKEN`, `SKIPPED`, `UNRECORDED` 횟수를 별도로 표시합니다.

각 그룹이 최소 3일 이상일 때만 그룹 간 비교를 제공합니다. 기록되지 않은 날은 실제 미복용 여부를 알 수 없다는 한계를 함께 표시합니다.

## 8. 시간대 분석

### 시간 구간

기록 시각을 **3시간 단위**로 묶어 분석합니다.

```
00:00~02:59
03:00~05:59
06:00~08:59
09:00~11:59
12:00~14:59
15:00~17:59
18:00~20:59
21:00~23:59
```

2시간 단위보다 3시간 단위를 선택한 이유:

- 최근 30일 데이터가 지나치게 많은 구간으로 흩어지는 것을 줄임
- 실제 발생 시각이 아닌 버튼 클릭 시각의 오차 영향을 줄임
- 사용자에게 충분히 구체적이면서 읽기 쉬움
- 약물 반응은 정확한 경계가 아니라 점진적으로 변화하므로 과도한 정밀도를 피함

CONCERTA 공식 라벨에서도 복용 후 초기 농도 상승과 이후 수 시간 동안의 점진적 변화가 설명되며, 안전성과 효과에 대한 시간별 반응은 완전히 규명되지 않았다고 안내합니다.

### 집계 규칙

- 복용, 감정·증상, 부작용, 실수·불편 로그를 기록 시각의 3시간 구간에 배치
- 동일 날짜·동일 구간·동일 태그가 여러 번 기록돼도 1회로 집계
- 단순 기록 횟수보다 해당 기록이 나타난 날짜 수와 날짜 비율을 우선 사용
- 해당 시간대 기록일이 3일 미만이면 패턴 분석에서 제외
- 인접 시간대와 차이가 작으면 주요 패턴으로 선정하지 않음

사용자 안내:
> 기록 버튼을 누른 시각을 3시간 단위로 묶어 분석했으며, 실제 복용 또는 증상 발생 시각과 다를 수 있어요.

허용 표현:
> 15시~18시 사이에 FOGGY 기록이 상대적으로 자주 나타났어요.

금지 표현:
> 복용 6시간 후 약효가 떨어졌어요.

## 9. 주요 분석 항목

### 복용 현황

- 선택 기간의 전체 예정 일정 수
- `TAKEN`, `SKIPPED`, `UNRECORDED` 횟수
- 복용 기록률
- 복용 여부 기록률
- 복용 시간대별 기록 패턴

### 날짜 그룹별 비교

다음 항목을 복용 기록이 있는 날, 건너뛰기만 기록된 날, 복용 여부가 기록되지 않은 날 사이에서 비교합니다.

- 목표 달성 점수
- UP, DOWN, TIGHT, FOGGY, CALM 및 사용자 입력 증상
- 부주의, 과잉행동, 충동성, 시간관리 실패, 인지 오류
- 부작용
- 수면 시간과 수면 질
- 식사 여부

### 시간대별 비교

- 시간대별 감정·증상 기록일 비율
- 시간대별 실수·불편 기록일 비율
- 시간대별 부작용 기록일 비율
- 복용 기록 시간대 이후 다른 시간대에 나타난 반복 패턴

### 부작용 분석

- 부작용 기록일 TOP 5
- 자주 기록된 시간대
- 선택 기간 내 증가·감소 경향
- 식사·수면 상태와 함께 나타난 패턴

### 메모 활용

메모는 통계 계산의 주 데이터가 아니라 맥락 보완 데이터로 사용합니다.

- 주요 증상·부작용 관련 문장 추출
- 업무 실수의 상황 설명
- 상담 시 보여줄 핵심 문장 요약
- Gemini 입력에는 분석과 관련된 메모 일부만 전달

## 10. 상담 및 약·용량 변경 감지

### 상담에 연결된 약

`UserMedication`은 `Consultation`, `MedicationDosage`, `startedAt`, `endAt`, 복용 일정을 보유합니다. 상담에 연결된 약 목록과 이전 상태를 비교하여 다음 변경을 감지합니다.

| 이전 상태와 상담 연결 정보 | 판정 |
| --- | --- |
| 이전에 없던 약 시작 | 약 추가 |
| 동일 약·동일 용량 | 유지 |
| 동일 약·다른 용량 | 용량 변경 |
| 이전 약 종료 | 약 중단 |
| 이전 약 종료 후 다른 약 시작 | 약 교체 |
| 동일 약·용량의 일정 변경 | 복용 일정 변경 |

비교 시 약은 `medicationId`, 용량은 `medicationDosageId`와 `amount`를 사용합니다.

### 상담 연결이 없는 기존 약

상담 연결이 없어도 최신 `UserMedication`을 중심으로 변경을 감지합니다.

- 최신 `startedAt`이 분석 기간 내에 있으면 최근 신규 시작으로 추정
- 동일 약의 직전 `UserMedication`과 용량이 다르면 용량 변경으로 추정
- 기존 약 종료 직후 다른 약이 시작되면 교체 가능성으로 추정
- 오래된 `startedAt`의 활성 약은 기존 복용 유지로 판단

현재 구조에는 처방 연장일이 별도로 없으므로 `처방이 연장됐다`고 확정적으로 표현하지 않습니다.

확정 가능한 변경과 추정 변경을 구분해 표시합니다.

| 감지 방식 | 표시 |
| --- | --- |
| 상담에 연결된 변경 | 확인된 복용 정보 변경 |
| 상담 연결 없이 `startedAt`, `endAt`, 직전 약을 이용한 감지 | 추정된 복용 정보 변경 |

### 변경 전후 비교

변경 기준일 우선순위:

1. 상담에 연결된 신규 `UserMedication.startedAt`
2. 이전 `UserMedication.endAt` 다음 날
3. 상담 일자

변경 전후 분석은 가능한 양쪽 기간 중 짧은 기간에 맞춰 동일한 길이로 비교합니다.

제공 조건:

- 변경 전후 각각 최소 7일
- 변경 전후 실제 일지 기록일 각각 최소 3일
- 조건 미충족 시 변경 전후 비교 생략
- 여러 약이 함께 변경됐다면 모든 변경 내용을 표시
- 변경과 기록 변화 사이의 인과관계를 단정하지 않음

허용 표현:
> 5월 22일 복용 정보 변경 이후 기간에는 이전보다 FOGGY 기록일이 적었어요.

금지 표현:
> 용량을 변경해서 FOGGY가 감소했어요.

## 11. 데이터 신뢰도와 기록 부족 처리

| 조건 | 처리 |
| --- | --- |
| 전체 일지 기록일 7일 미만 | 리포트 생성 불가 |
| 비교 그룹 중 한쪽이 3일 미만 | 해당 그룹 비교만 생략 |
| 시간대 기록일 3일 미만 | 해당 시간대 패턴 제외 |
| 변경 전후 기간 각각 7일 미만 | 변경 전후 비교 생략 |
| 변경 전후 일지 기록일 각각 3일 미만 | 변경 전후 비교 생략 |
| 약물 관련 기록이 지나치게 부족 | 약물 관련 비교 생략 |

가능한 분석은 계속 제공하며, 생략된 분석마다 이유를 표시합니다.

예시:
> 건너뛰기만 기록된 날이 충분하지 않아 해당 비교는 제공하지 않아요.

> 이 시간대의 기록이 충분하지 않아 반복 패턴으로 판단하지 않았어요.

## 12. 사용자 화면 구성

### 한눈에 보기

- 분석 기간과 생성일
- 복용 기록률 및 복용 여부 기록률
- 주요 기록 패턴 최대 3개
- 데이터 한계 안내

예시:
> 선택한 30일 동안 예정된 60회 중 48회의 복용 기록이 있어요.

> 15시~18시 사이에 FOGGY 기록이 상대적으로 자주 나타났어요.

> 최근 복용 정보 변경 이후 기간에는 이전보다 시간관리 어려움 기록일이 적었어요.

### 근거 확인

모든 설명에 실제 수치, 표본 수, 근거 날짜를 연결합니다.

- 복용 기록이 있는 날의 업무 목표 평균: 7.1점 · 22일
- 건너뛰기만 기록된 날의 업무 목표 평균: 5.5점 · 5일
- 관련 기록 날짜 열기

### 상담 준비

Gemini가 기록에 기반해 상담 시 확인할 질문을 최대 3개 생성합니다.

- 오후 시간대에 FOGGY 기록이 반복되는 점
- 복용 정보 변경 이후 입마름 기록이 달라진 점
- 복용 여부 기록이 누락된 시간대가 많은 점

---

## 13. 서버와 Gemini 역할 분리

### 서버 담당

- 전체 예정 복용 일정 생성
- `TAKEN`, `SKIPPED`, `UNRECORDED` 판정
- 복용 기록률과 복용 여부 기록률 계산
- 날짜 그룹 분류와 비교
- 3시간 단위 시간대 집계
- 상담 및 약·용량 변경 감지
- 변경 전후 비교
- 표본 수, 근거 날짜, 데이터 한계 생성
- 메모 후보 선정 및 개인정보 제거

### Gemini 담당

- 서버가 발견한 주요 패턴 최대 3개 설명
- 관련 메모 요약
- 상담 시 확인할 질문 최대 3개 생성
- 데이터 부족 및 해석 한계 설명

Gemini는 새로운 통계를 계산하거나, 제공되지 않은 패턴을 생성하거나, 약효를 판정하지 않습니다.

## 14. Gemini 입력 데이터와 동의

### 호출 대상

| 사용자 상태 | 제공 기능 |
| --- | --- |
| AI 분석 미동의 | 서버 계산 통계, 차트, 근거 수치 |
| AI 분석 동의 | 기본 통계 + Gemini 요약 + 상담 질문 |
| 동의 철회 | 신규 Gemini 호출 중단, 기본 통계 계속 제공 |

Gemini는 사용자가 리포트 생성을 요청할 때만 호출합니다. 화면을 조회할 때마다 호출하지 않습니다.

Gemini 호출 조건:

- AI 분석 동의 완료
- 분석 기간 및 기록 수 조건 충족
- 서버 분석 스냅샷 생성 성공
- 동일 데이터로 생성된 기존 리포트가 없음

Gemini 호출 또는 출력 검증에 실패해도 기본 통계 리포트는 정상 제공합니다.

### 전달 데이터

- 분석 기간
- 서버 계산 통계와 근거 ID
- 약 이름, 용량, 복용 기록 시각
- 표본 수와 데이터 한계
- 분석과 관련된 메모 발췌
- 사용자 정의 증상·부작용 이름

### 제외 데이터

- 사용자 ID
- 이름, 이메일 등 직접 식별 정보
- 분석과 무관한 기록
- 전체 메모 원문
- 메모에 포함된 타인의 개인정보

운영 환경에서는 유료 Gemini API를 사용합니다. AI 분석은 선택 기능으로 제공하며, 동의 화면에는 민감정보 처리, 국외 이전, 처리 목적, 데이터 항목, 동의 철회 방법, 의료 조언이 아니라는 안내를 포함합니다.

## 15. Gemini 출력 및 안전성 검증

Gemini 출력은 자유 텍스트가 아니라 구조화된 JSON으로 받습니다.

```json
{
  "summary": "선택 기간의 기록 요약",
  "insights": [
    {
      "category": "TIME_PATTERN",
      "title": "오후 시간대 FOGGY 기록 증가",
      "description": "15시~18시 사이에 FOGGY 기록이 상대적으로 자주 나타났어요.",
      "evidenceIds": ["TIME_PATTERN_FOGGY_01"],
      "confidence": "MEDIUM",
      "limitation": "기록 버튼을 누른 시각 기준이에요."
    }
  ],
  "consultationQuestions": [
    "오후 시간대에 FOGGY 기록이 반복되는 점을 의료진과 확인해 보세요."
  ],
  "disclaimer": "기록된 패턴을 요약한 내용이며 의료적 판단이 아닙니다."
}
```

검증 순서:

```
Gemini 응답
→ JSON Schema 검증
→ 근거 ID 존재 검증
→ 숫자 일치 검증
→ 금지 표현 검증
→ 결과 저장 및 노출
```

허용 표현:

- 복용 기록이 있는 날에 목표 점수가 높게 기록됐어요.
- 오후 시간대에 FOGGY 기록이 상대적으로 자주 나타났어요.
- 담당 의료진과 함께 확인해 보세요.

금지 표현:

- 이 약은 효과가 있습니다.
- 약효가 떨어졌습니다.
- 복용량을 늘리거나 줄이세요.
- 부작용이므로 복용을 중단하세요.
- 특정 질환으로 진단됩니다.

검증 실패 시 Gemini 결과를 노출하지 않고 서버가 만든 안전한 기본 문장으로 대체합니다.

## 16. 분석 스냅샷

Gemini에는 원본 전체를 그대로 전달하지 않고 서버가 계산한 분석 스냅샷과 필요한 원본 일부를 함께 전달합니다.

```json
{
  "period": {
    "start": "2026-05-15",
    "end": "2026-06-13",
    "days": 30
  },
  "dataQuality": {
    "recordedDays": 24,
    "confidence": "MEDIUM",
    "limitations": []
  },
  "adherenceSummary": {},
  "dailyMedicationStatuses": [],
  "dayGroupComparisons": [],
  "timeWindowPatterns": [],
  "sideEffects": [],
  "medicationChanges": [],
  "memoEvidence": []
}
```

동일한 원본 데이터와 동일한 분석 정책은 항상 동일한 스냅샷을 생성해야 합니다.

## 17. 리포트 저장 및 재생성

```
medication_analysis_report
- id
- user_id
- period_start
- period_end
- status
- source_data_hash
- snapshot_json
- ai_result_json
- model_name
- prompt_version
- generated_at
```

재생성 정책:

- 생성 당시 원본 데이터 해시 저장
- 동일 기간·동일 데이터면 기존 리포트 재사용
- 원본 일지 또는 복용 기록 변경 시 기존 리포트를 `OUTDATED` 처리
- 사용자에게 최신 기록으로 새 리포트가 필요하다고 안내
- 사용자가 직접 재생성
- 기존 리포트는 당시 경과 기록으로 보존
