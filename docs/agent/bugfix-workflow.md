# 버그 수정 워크플로

1. **재현** — 실패하는 케이스를 먼저 **테스트로** 재현한다(회귀 방지의 출발점).
2. **원인 좁히기** — [observability](../engineering/observability.md) 로 로그/스택/응답을 본다. 증상 아닌 근본 원인을 찾는다.
3. **영향 파악** — 같은 버그가 다른 경로에도 있는지 확인(동일 패턴 검색).
4. **최소 수정** — 근본 원인을 고친다. 우회/땜질은 지양하고, 불가피하면 사유를 남긴다.
5. **테스트 green** — 1의 재현 테스트가 통과하는지 + 기존 테스트 회귀 없는지 확인.
6. **문서** — 동작/계약이 바뀌었으면 관련 문서 갱신. 새 함정이면 해당 워크플로의 "흔한 실수"에 추가.
7. **검증** — `scripts/agent/verify`.

## 원칙

- 원인 불명 상태로 상태코드/예외만 바꿔 덮지 않는다.
- 데이터 손상·보안 관련 버그는 [확인 기준](../../AGENTS.md#8-확실하지-않을-때-사람에게-확인할-기준)에 해당하면 사람 확인.
