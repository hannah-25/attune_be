# 실행 계획: dev 100 VU 부하 테스트

- 상태: completed
- 작성/실행: Codex / 2026-07-28

## 목표

`api-dev.attune-me.com`에서 100 동시 사용자 기준의 응답 시간·오류율·서버 자원 사용량을 측정하고, 전용 테스트 데이터와 관측 설정을 종료 후 정리한다.

## 실행 범위

- 80% 조회, 20% 복약 빠른 기록
- 100개의 `loadtest-*.attune.invalid` 전용 계정
- k6 단계: 1, 10, 25, 50, 75, 100 VU
- loadtest 프로파일에서만 EC2 loopback management port의 metrics 허용

### 시나리오와 측정 기준

- 각 VU는 로그인 후 조회 요청과 복약 기록 요청을 80:20 비율로 반복했다. 요청 사이에는 1~3초를 대기해, 단순한 최대 처리량 시험보다 사용자 행동에 가까운 부하를 만들었다.
- `HTTP 요청`은 테스트 기간에 서버가 처리한 모든 API 호출 수다. 로그인·조회·기록 호출이 모두 포함되므로, 사용자 수와 같은 의미는 아니다.
- `오류율`은 HTTP 요청 실패 비율이다. 5xx 및 기대한 응답이 아닌 경우를 실패로 처리했고, 1% 미만을 통과 기준으로 삼았다.
- `p95`는 요청의 95%가 이 시간 안에 끝났다는 뜻이다. 예를 들어 100 VU의 87.01 ms는 100건 중 95건이 약 0.087초 이내에 완료됐음을 의미한다. 일부 느린 요청을 숨기지 않도록 p99도 2초 미만 기준으로 확인했다.
- 각 최종 단계는 약 12분 동안 수행했다. 단계 전환 중 문제가 보이면 다음 단계로 올리지 않는 방식으로 진행했다.

## 최종 결과


| 동시 사용자 | HTTP 요청 | 오류율 | p95      | 해석          |
| ------ | -------: | ---: | --------: | ----------- |
| 10 VU  | 8,971   | 0%  | 59.92 ms | 낮은 동시성 기준선  |
| 25 VU  | 22,228  | 0%  | 63.28 ms | 지연 증가가 작음   |
| 75 VU  | 64,372  | 0%  | 88.32 ms | DB 대기 없이 통과 |
| 100 VU | 86,016  | 0%  | 87.01 ms | 목표 동시성에서 통과 |


- 100 VU: 약 115.7 HTTP 요청/초, p99 2초 미만, 모든 k6 threshold 통과
- 100 VU 관측: Hikari pending 0, JVM heap 약 307 MB, 컨테이너 메모리 약 338 MiB, CPU 약 94%
- 결론: 측정한 오류율/지연시간 목표는 통과했다. DB 커넥션 풀 대기는 없었고, 현 인스턴스에서는 CPU가 다음 확장 한계 후보이다.

### 100 VU 결과 해석

- 오류율 0%와 모든 기능 검증 통과는, 이 시나리오에서 조회와 복약 기록이 정상적으로 처리됐다는 의미다. 단순히 HTTP 연결만 성공한 결과가 아니다.
- p95가 100 ms 미만이고 p99 기준도 통과했으므로, 이번 시험 범위에서는 체감 가능한 지연 악화가 관측되지 않았다.
- Hikari `pending=0`은 커넥션을 기다린 요청이 없었다는 지표다. 따라서 이번 결과에서 MySQL 커넥션 풀 크기를 먼저 늘릴 근거는 없다.
- CPU 약 94%는 인스턴스 여유가 거의 없다는 신호다. 더 높은 동시성, 더 긴 지속 시간, 실제 외부 연동이 포함되면 지연이나 오류가 발생할 가능성이 커진다. 다음 증설 시험은 CPU를 우선 관찰 대상으로 삼는다.

### 이번 시험의 한계

- dev 환경의 단일 인스턴스에서 수행한 결과이므로 운영 트래픽·운영 데이터 크기·운영 네트워크 성능을 보장하지 않는다.
- 약 12분 시험은 짧은 순간 부하 확인이다. 메모리 누수, DB 커넥션 누수, 장시간 큐 적체는 별도의 장시간 시험이 필요하다.
- 이 시나리오는 조회와 복약 기록에 한정된다. AI 리포트, 메일·푸시, 외부 OAuth·Calendar처럼 외부 서비스를 호출하는 흐름은 의도적으로 제외했다.

### 후속 판단 기준

- 같은 인스턴스에서 100 VU를 넘겨야 하면, 먼저 CPU 사용률이 지속적으로 80%를 넘는지와 p95/p99 증가를 함께 확인한다.
- CPU가 병목으로 재현되면 인스턴스 상향 또는 수평 확장 검토가 우선이다. Hikari pending이 발생할 때만 DB 커넥션 풀·DB 성능을 추가로 조사한다.
- 운영 전에는 운영과 유사한 데이터 크기 및 외부 연동 정책을 반영한 별도 시험을 수행한다.
